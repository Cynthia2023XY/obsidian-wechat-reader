# WeChat Reader · RSS 阅读

中文说明 | [English](README.en.md)

Obsidian 桌面 RSS 阅读器：在右侧栏管理普通 RSS、Atom 和微信公众号，在原生弹窗中阅读、切换、收藏与归档。界面直接使用 Obsidian 主题变量，自动跟随深色、浅色主题。

## 首次安装前请注意

**从 Obsidian 社区插件页面首次安装，不会一起下载公众号采集引擎。** 标准插件文件可直接使用普通 RSS/Atom；首次使用微信公众号功能，还需要手动安装完整包中的 `engine/`。

| 安装方式 | 普通 RSS/Atom | 微信公众号 |
| --- | --- | --- |
| 社区插件页面安装，或只安装三个标准插件文件 | 可直接使用 | 需另外下载完整包并安装 `engine/` |
| 下载完整 ZIP，按完整目录安装 | 可使用 | 已包含引擎，无需另行下载 |

引擎安装完成后，插件会在需要时自动启动它，用户无需手动运行，也无需另装 Node 或 Python。当前完整包仅支持 macOS Apple Silicon（M 系列芯片）。

## 安装和使用

1. 使用公众号功能时，从 [1.0.0 发布页](https://github.com/Cynthia2023XY/obsidian-wechat-reader/releases/tag/1.0.0) 下载 `wechat-reader-1.0.0-macos-arm64.zip`（不要下载 Source code 源码包），解压后将完整 `wechat-reader/` 放入笔记库 `.obsidian/plugins/`，保留 `engine/`，启用插件。已安装标准插件时，补充或覆盖完整包文件，并保留原有 `data.json` 和 `cache/`。仅使用 RSS/Atom 时，可在社区插件页面安装（目录中可用时），或手动安装 `main.js`、`manifest.json`、`styles.css`。自定义配置目录的笔记库请使用实际路径。
2. 点击 RSS 图标或执行“打开 RSS 阅读侧栏”。首次安装和一期升级默认停靠**右侧栏**，后续保留用户拖动的布局。
3. 点击 `+` 添加 RSS/Atom XML 地址。菜单支持 OPML 导入预览和导出；重复 URL 保留原源，同名源可分别放在不同分组。右键源可以修改名称、分组、刷新周期或停止自动刷新；历史缓存和阅读状态保留。
4. 点击文章打开原生阅读弹窗。`← / →` 切换前后文章，`↑ / ↓` 滚动正文，`Esc` 关闭；输入框、输入法和其他弹窗不受影响。打开时冻结当前已展示的文章队列，标记已读后不会跳篇，首尾不循环。
5. 顶部“全部文章 / 未读 / 已读 / 收藏”直接展示跨来源文章，按发布时间倒序排列，文章注明来源；展开“订阅源”可切换到单个来源。每个列表默认显示 50 篇，底部“加载更多”每次追加 50 篇，数量统计全部匹配文章；切换入口保留本次视图内的加载条数和滚动位置。打开正文、摘要或失败提示后自动已读；后台预取和采集失败不会自行标记。文章、订阅源和分组右键支持标记为已读，右上角可全部标为已读并撤销；“全部文章”和“已读”不显示数字。已读、收藏、归档关联仅属于当前笔记库。
6. 弹窗内“保存为 MD”将正文和本地图片保存至设置目录，不切走阅读弹窗；重复保存保留原笔记及用户编辑。正文版本更新时可确认另存副本。“复制文章”复制清理后的 Markdown 和原文链接，图片使用公开地址或文字占位，不复制本机凭据。

## 更新方式与原因

Obsidian 的标准更新机制只下载 `main.js`、`manifest.json` 和可选的 `styles.css`，不会解压 Release 完整包并安装 `engine/`。参见 [官方发布说明](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin)。

- 仅修改界面的版本，通常在插件页面更新即可，以发行说明为准。
- 修改公众号采集内核的版本（包括 **1.0.0**），需要同时下载该版本完整包并替换 `engine/`。关闭所有使用该采集程序的笔记库，等待采集结束和程序退出后再替换，随后重新打开 Obsidian。同机多个库均使用公众号时，需要逐一更新相关库。保留原有设置、缓存和归档笔记。
- 插件页面显示新版本号，只代表标准插件文件已更新，不能证明独立引擎也已更新。插件不会自动下载或安装引擎。

这样设计是为了随包提供固定 Node 环境，并让多个笔记库共享 SQLite、采集队列与文章存储；普通 RSS/Atom 则不必启动公众号程序。额外安装步骤是当前独立引擎架构的取舍，并非所有 Obsidian 插件都需要如此安装。

## 订阅配置

插件设置提供“当前订阅链接（只读）”：显示全部 RSS/Atom 地址和公众号已保存的原文链接，包含已暂停的源，可复制但不能编辑。公众号尚未保存链接时明确提示，不以通用主页代替。

- “导出订阅配置”将统一 JSON 文件保存到笔记库根目录，包括名称、地址、分组、开关、刷新间隔及公众号恢复定义；不导出登录凭据、文章缓存或阅读记录。私有 RSS 地址中的必要查询参数会保留，请自行保管导出文件。
- “导入订阅配置”选择本插件导出的 JSON，先预览再确认。按 RSS 地址和公众号身份去重，保留已有订阅设置，仅补齐缺失恢复信息；无效文件整份拒绝，保存失败回滚，不产生部分导入。
- 配置导入不要求联网验证。普通 RSS 按计划刷新；公众号需启用功能并在本机扫码后自动恢复。只有名称的旧公众号仍需补充原文链接。
- 侧栏原有 OPML 导入导出继续保留，适用于普通 RSS/Atom。

## 微信公众号

普通 RSS 无需开启公众号功能、登录微信或运行采集程序。在侧栏菜单扫码登录微信读书，添加公众号时粘贴文章链接，解析真实身份并确认显示名称。

- 公众号能力使用**独立 TypeScript/Node 运行时**，随包携带 Node，无需用户安装 Node 或 Python。只有启用公众号能力才连接或启动。
- 首轮最多 10 篇，后续自动同步仅检查近期文章，最多 30 篇，不再自动回补历史；正文请求间隔 5 秒，全局串行，多个笔记库共享一份 SQLite 和采集队列。旧历史游标保留，右键公众号选择“获取更多历史文章”可手动获取一页（最多 10 篇）。
- 浏览器兜底使用本机 Chrome 或 Edge。访问限制、失效授权需要在手机处理或重新扫码；失败和永久不可用条目不算正文成功。
- 右键公众号可复制**本机持续 RSS 订阅地址**。固定专用回环端口和源级只读令牌与管理密钥隔离；需要本机采集程序运行，不提供公网订阅或退出 Obsidian 后的后台守护。
- 默认省电模式：插件以轻量计时器等待到期，再启动服务，任务完成后空闲约 15 秒释放租约；无其他库、任务或扫码需求时服务退出。侧栏不做空闲网络轮询。Obsidian 关闭或睡眠期间不采集，恢复后每个过期源最多补一轮。
- 设置中可切换常驻模式，以供其他阅读器持续读取本机 RSS 地址；省电模式下此地址只在服务运行时可访问。
- 刷新设置使用小时：普通 RSS 新订阅默认 1 小时，新公众号默认随机 2～3 小时，已有间隔保持原值。
- 阅读弹窗默认宽度为 720px，可在设置“阅读弹窗宽度”中调整为 480～1000px；左右正文边距 28px，小窗口限制在视口内。

## 数据与一期迁移

- 普通 RSS 缓存位于当前库 `.obsidian/plugins/wechat-reader/cache/`，按源分片，图片按文章隔离；条件请求、失败退避和增量合并保留历史。
- 点击全部已读会记录本库时间基准，此后发现的基准之前发布的公众号文章默认已读；手动未读优先，发布时间未知的文章仍为未读。撤销同时恢复旧基准。
- 设置中的“公众号缓存管理”先按 UTC 日期预览，再由用户确认清理共享正文和图片；保留索引、阅读状态和归档笔记。已登记的其他笔记库必须关闭并可访问，库根目录下配置目录中的收藏和归档文章会被排除；未登记或无法检测的笔记库无法自动核对，请勿清理其依赖的数据。清理影响其他库与本机 RSS 的共享离线正文；可重新获取，不保证远端仍可用。本库已缓存正文继续可读。
- 公众号索引和计划通过私有 `runtime/schedule.json` 快照恢复，浏览过的正文和图片缓存在当前库 `cache/`，缓存完整时不启动服务。首次补读或内容更新时短暂连接；服务故障时可继续读取已有正文。
- 当前库 `data.json` 保存订阅配置、阅读状态和笔记关联，不保存公众号凭据或管理密钥。私有 RSS 地址可能含订阅者自己的查询令牌，请自行决定是否同步配置。
- 公众号共享数据仍位于 `~/Library/Application Support/Obsidian WeChat Reader/`：SQLite、版本化正文图片、私有 `data/credentials/`、运行发现文件。
- 公众号的可迁移定义保存在本库 `data.json` 的 `wechatFeeds[].wechat`：稳定身份、公开原文链接、显示名称、暂停/订阅状态和刷新间隔。新电脑同步插件配置后，重新扫码即可自动恢复信息完整的订阅，无需复制登录凭据。后台仅重建缺失账户，不覆盖本机其他库已有账户的设置。
- 已有共享采集记录会自动补齐定义；旧缓存中有可靠身份时也会补齐。只有名称和内部 ID 的旧条目，需要右键“补充恢复链接”填写一次任意原文，并校验属于同一公众号；此后可随配置迁移。也可在更多菜单中选择“恢复本库公众号订阅”重试。
- 新电脑恢复后会重新拉取近期文章，阅读、收藏和归档关联保留；完整历史文章并不会仅靠订阅定义自动迁移。如需保留所有旧正文和图片，可在停用两端插件后迁移旧电脑整个 `~/Library/Application Support/Obsidian WeChat Reader/` 目录。微信登录凭据始终留在本机私有目录，不写入订阅配置。
- 首次 TS 接管前生成 SQLite 和凭据回退快照；沿用原文章 ID、URL 别名、账号池格式和正文目录，保留已读、收藏、归档及用户编辑。不能让旧 Python 进程与新 TS 进程同时写入共享目录。
- `companion/` 保留一期历史实现和 MIT 上游来源，**当前构建、运行、安装包不调用 Python**；离线签名对照样例有固定测试覆盖。

## 许可与运行说明

本插件采用 [MIT License](LICENSE)。旧版采集实现参考并保留 [wechat-mp-tools](https://github.com/x554960766/wechat-mp-tools) 的 MIT 许可；第三方运行依赖的许可随完整包附带。

普通 RSS/Atom 会联网访问用户填写的源和文章图片地址。公众号功能需要微信读书账号，会访问微信/微信读书服务以扫码、查询公众号和下载正文，必要时使用本机 Chrome 或 Edge。插件会读写笔记库之外的本机共享目录，保存凭据、文章与采集进度，位置详见下文。不包含遥测、广告或付费功能，不自动下载安装或更新自身及依赖。

完整包目前仅适用于 macOS Apple Silicon。仅安装标准 `main.js`、`manifest.json`、`styles.css` 时可使用普通 RSS/Atom；公众号功能还需用户手动从本 Release 的完整包中复制 `engine/`。没有附属程序时会给出安装提示，不会自动下载依赖。

## 开发与验证

开发需要 Node 26+（使用原生 `node:sqlite`）；安装用户无需额外安装运行时。

```sh
npm ci
npm test
npm run test:companion
npm run build
npm run package:companion
npm run test:package
WECHAT_READER_TEST_VAULT="/你的测试笔记库路径" npm run deploy:test
```

`test:companion` 使用临时目录和网络夹具，不读取真实授权。`test:legacy` 仅供一期历史回归，需要单独 Python 虚拟环境。当前包针对 macOS Apple Silicon；移动端、本机之外的 RSS 服务、LaunchAgent、完整历史回补不在本次范围。当前版本号为 1.0.0，内核通过 `engineVersion: ts-1` 与旧实例区分，并要求 `power-save`、`portable-subscriptions`、`bounded-history` 和 `cache-cleanup` 能力；1.0.0 的公众号功能应安装本版本完整包中的 `engine/`。

安装和回归结果见 `VALIDATION.md`。私有发现文件、二维码、Cookie、Token 不得复制到日志、报告或 Git。

## 公众号图片存储

公众号正文保存在本地，图片在阅读时直接从微信 HTTPS 图片 CDN 加载，不再批量保存到共享存储。主动归档时才下载为笔记库附件。旧图片清理工具默认仅预览，操作前需停止采集程序。详见 [方案说明](docs/remote-images.md)。
