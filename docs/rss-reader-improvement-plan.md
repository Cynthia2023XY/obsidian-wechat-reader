# RSS 阅读体验与省电改造方案

日期：2026-10-25

状态：已按本方案完成代码实现、自动化验证与完整包构建；Obsidian 内的视觉和真实账号体验待测试。

## 1. 实施前核实的现状

| 项目 | 当前实现 | 影响 |
| --- | --- | --- |
| 普通 RSS/Atom | 默认 60 分钟刷新；每 15 秒检查是否到期；设置以分钟输入，最低 5 分钟 | 检查周期不是实际拉取周期；不依赖公众号服务 |
| 公众号 | 默认在每轮结束后随机等待 60～90 分钟；允许范围 60～1440 分钟 | 自动调度在独立服务内部，不能只关闭进程而不迁移唤醒逻辑 |
| 服务生命周期 | 启用公众号后，插件加载时连接；客户端每 25 秒续租；租约有效期 90 秒 | 插件运行期间服务通常持续在线 |
| 侧栏 | 可见时每 5 秒读取公众号账户和全部文章列表 | 即使实现空闲退出，也会被侧栏再次启动 |
| 公众号缓存 | 列表主要在内存中；正文、图片通过服务接口读取 | 省电模式需要支持服务关闭时的本地阅读 |
| 文章已读 | 文章右键已有“标为已读/标为未读”；成功展示正文时自动已读 | 无正文或请求失败时不会自动已读 |
| 错误提示 | `EMPTY_CONTENT` 使用“页面缺少有效正文，未计入阅读成功” | 实际是采集失败，文案却混入阅读状态含义 |
| 聚合入口 | 全部文章、未读、收藏，均支持非零数字徽标 | 全部文章数随保留的历史持续增长；缺少已读筛选 |
| 弹窗 | 最大宽度 960px；正文宽度约 700px，剩余宽度转为居中留白 | 外框与正文之间的左右空白偏大 |

核对位置：`src/feeds/service.ts`、`src/runtime/manager.ts`、`src/views/reader.ts`、`src/views/article-modal.ts`、`src/views/feed-modals.ts`、`src/views/wechat-modals.ts`、`runtime-ts/core.ts`、`runtime-ts/jobs.ts`、`runtime-ts/server.ts`、`runtime-ts/collector.ts`、`styles.css`。

## 2. 拉取间隔改用小时

### 界面与默认值

- 普通 RSS：设置名称改为“刷新间隔（小时）”，新订阅默认 **1 小时**；支持小数，精确到整分钟，保留原有最低 5 分钟能力，校验提示说明最低值。
- 公众号：保留随机间隔机制，将输入改为“最短间隔（小时）”“最长间隔（小时）”，新订阅建议默认 **2～3 小时**；范围仍为 **1～24 小时**，最短不得大于最长。
- 公众号设置说明：“每轮同步结束后，在此范围内随机安排下一次同步。”
- 设置处展示下一次计划刷新时间；失败重试优先时显示“下次重试”，避免让用户误认为未遵守间隔。
- 修改间隔后立即重算下次时间：普通源按最近检查时间，公众号按最近同步结束时间；已经到期的只安排一轮。运行中的任务使用新间隔计算下一轮。

### 兼容策略

内部继续保存分钟字段和既有 API 字段，界面负责小时换算与整分钟校验，避免无必要的数据迁移。旧的 60 分钟显示 1 小时，90 分钟显示 1.5 小时；不自动将现有公众号改成 2～3 小时。

说明：这是使用本地代码核实后的产品配置建议，不承诺具体节电比例。

## 3. 公众号服务改为按任务启动

### 两种运行方式

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| 省电模式（默认） | 到期同步、扫码、修改公众号设置、缺失缓存补读等操作时启动；任务结束后退出 | 在本插件阅读 |
| 常驻模式（可选） | 保持共享服务在线，继续提供本机 RSS HTTP 地址 | 其他阅读器持续访问本机 RSS 地址 |

普通 RSS 始终由插件直接拉取，不启动公众号服务。

省电模式下，复制本机 RSS 地址时提示：“此地址仅在服务运行时可用；需要持续订阅时，请启用常驻模式。”不因复制地址自动切换模式。

### 调度与唤醒

1. 插件加载时先读本地快照，直接显示列表，不立即连接公众号服务。
2. 将普通 RSS 和公众号的最近到期时间交给插件侧轻量调度器，用一个可重设的 `setTimeout` 等待；计时回调核对实际时间和当前配置。
3. 公众号账户、下一次同步时间及阻塞原因仍以共享服务数据库为权威。服务在任务完成、配置变更时原子导出共享调度快照，位于用户私有目录；插件只读该快照，不直接读写 SQLite。
4. 到期后启动或复用共享服务，获取最新状态，再由服务确认到期账户并去重入队。多个库同时唤醒，也只执行同一账户的一份有效任务。
5. 本批任务结束后，保存列表、正文/资源缓存与最新调度时间，然后释放任务会话。下一次等待由插件计时器负责。
6. 启动失败采用有限重试和退避，不因侧栏打开、健康检查或续租失败无限重新启动。需要扫码/验证时暂停相关账户的自动唤醒并显示处理入口。
7. Obsidian 关闭或电脑休眠期间不启动服务；恢复后核对时间，每个过期订阅最多补一轮，不补跑每个错过的周期。

快照缺失或格式过旧时允许一次初始化连接；初始化成功后落盘，避免每次重开都启动。其他笔记库修改调度时，通过快照文件变更通知重设计时器；唤醒时仍重新校验，以处理通知遗漏、并发及过期快照。

### 任务会话与安全退出

- `RuntimeManager` 增加可释放的操作会话，以“获取 → 执行 → finally 释放”管理；会话内的多个接口请求复用一次连接。
- 只在持有活跃会话时续租。扫码窗口、采集任务、正文/资源读取和设置提交均覆盖完整操作周期。
- 同步接口返回任务 ID 只代表入队，必须等到任务进入结束状态且本地缓存写入完成，才能释放本次会话。
- 引用归零后允许 **15 秒**空闲宽限，吸收连续点击和文章切换；期间有新操作则取消退出计划。
- 服务必须同时满足：无有效客户端会话、无常驻需求、无运行/排队任务、无扫码会话、无未完成请求，才关闭。退出等待已有写入收尾，并释放服务持有的浏览器等资源。
- 一个库只能释放自己的会话，不能直接杀死其他库正在使用的共享进程。检测到过期客户端时回收会话，同时处理扫码过期和孤立任务，避免永远无法退出。
- 空闲退出后清理旧客户端引用；下一次操作重新发现实例和获取租约。共享实例正在退出时，等待其退出后再尝试启动，避免复用已关闭连接或并发拉起。
- 开启常驻模式的库持有常驻租约；所有库均释放常驻需求后，服务才恢复空闲退出。

现有“最后租约消失就调用 close()”会停止调度，并可能中断未完成批次，必须一并改造，不能直接沿用。

### 本地阅读与面板更新

- 取消侧栏无任务时的 5 秒接口轮询；保留本地数据变化事件。仅有实际采集任务时轮询任务进度，结束立即停止。
- 公众号列表快照写入本库缓存，重启后可直接恢复。正文和图片作为可重建的本库阅读缓存，按文章 ID 与内容版本保存，下载完成后原子提交。
- 阅读与归档优先使用本地缓存；首次缺失时以短会话连接服务读取并补齐。缓存存在但服务暂不可用时继续展示已有内容。
- 图片继续按需加载，不在每轮采集结束后向每个笔记库额外复制全部历史资源；缺失图片允许短会话补读。
- 不将令牌、端口发现信息、凭据放入阅读缓存。缓存 HTML 仍走现有清理流程。
- 多库通过共享调度/数据版本快照获知变更，必要时短会话更新索引；不能各自持续轮询全部正文。

## 4. 已读操作与筛选

### 操作入口

| 位置 | 文案 | 范围 |
| --- | --- | --- |
| 单篇文章右键 | 标记为已读；已读文章则为“标记为未读” | 当前文章 |
| 订阅源右键 | 标记为已读 | 该 RSS/Atom/公众号的全部已知文章 |
| 分组标题右键 | 标记为已读 | 该分组下所有源的全部已知文章 |
| RSS 面板右上角 | 全部标为已读 | 当前库中全部已知文章，包括停用订阅的历史 |

将“每一类订阅”同时覆盖为订阅源和分组，避免右键入口只覆盖其中一层。

- 右上角使用双勾图标，悬停和无障碍名称均为“全部标为已读”，放在刷新按钮旁。
- 批量操作覆盖未展开、分页未显示以及失败/无正文文章，不受当前未读、收藏等筛选限制。
- 点击时冻结目标文章 ID；操作期间新拉取的文章仍保持未读。
- 统一阅读状态方法，只修改 `read`，保留收藏、归档路径和内容版本；一次持久化、一次列表通知。
- 操作完成提示影响篇数，并提供一次“撤销”入口，恢复这些 ID 操作前的阅读值；随后发生新的阅读状态操作时撤销失效，避免覆盖后续操作。
- 已全部已读时提示“没有未读文章”，不产生多余写入。
- 持久化失败需回滚本次内存变更并提示失败，不留下界面成功但重启丢失的状态。

### 聚合栏目

顺序调整为：**全部文章 → 未读 → 已读 → 收藏**。

- “全部文章”和“已读”不创建数字徽标。
- “未读”、订阅源保留未读数量；“收藏”保留现有收藏数量。零数量继续隐藏。
- “已读”仅筛选当前库 `read === true` 的文章；未读包含无状态或 `read !== true` 的文章。
- 这些是现有订阅树上的筛选，保留源展开状态与稳定的弹窗导航队列。

## 5. 无正文文章不再一直占据未读

采集状态与阅读状态独立：**已读表示用户已处理这条信息，不等于正文采集成功。**

| 情况 | 阅读状态 | 采集状态 |
| --- | --- | --- |
| 后台下载失败，用户没有打开 | 保持原值 | 保留失败信息 |
| 用户打开文章，正文正常展示 | 标为已读 | 保持原值 |
| 用户打开文章，显示无正文/不可用提示 | 提示成功呈现后标为已读 | 继续失败或不可用 |
| 正文请求异常，弹窗展示对应文章的失败提示 | 标为已读 | 不伪造新采集结果 |
| 用户右键或批量标记 | 按用户操作更新 | 不变 |
| 用户在弹窗外手动标为未读 | 保持手动未读 | 不因迟到的图片/正文响应再次改回已读 |
| 快速切走或关闭，旧请求才返回 | 不自动改动旧文章 | 保持采集结果 |
| 之后正文重试成功 | 保留现有阅读状态 | 更新为采集成功 |

将自动已读放在统一的“当前条目已展示”阶段，正文成功与错误展示复用同一个方法。更新前检查文章 ID、请求序号、弹窗是否仍打开，以及展示开始后是否有手动阅读状态操作。

文案调整：

- 采集错误：“页面缺少有效正文，正文下载未成功。”
- 弹窗辅助提示：“可打开原文查看，或稍后重试获取正文。”
- 错误页提供“打开原文”“重试获取正文”；重试沿用现有服务端任务队列和去重机制，重复点击期间禁用按钮。
- 列表同时展示阅读与内容状态，例如“已读 · 正文获取失败”，避免只显示“正文未就绪”而无法判断已读。

不通过伪造空正文、修改采集成功计数或删除失败文章来清理未读。继续保留现有重试机制；本次不额外增加高频重试。

## 6. 收窄阅读弹窗

建议固定目标宽度 **800px**，无需测量 Obsidian 中心编辑区。只保留小窗口下防溢出的视口上限。

```css
.modal.wr-article-modal {
  width: 800px;
  max-width: calc(100vw - 48px);
}
.wr-modal-body {
  padding: 24px 28px 32px;
}
```

- 取消正文原有按 700px 居中计算的大边距，800px 外框下正文约 744px，实际可用宽度另扣边框和滚动条。
- 顶部和底部左右基础边距统一为 20px；顶部右侧继续给关闭按钮保留空间。
- 保留当前高度策略、正文内部滚动、上下篇及快捷键。
- 沿用主题字号；标题允许自然换行，图片不超正文宽度，代码块/宽表格在内容区内横向滚动。
- 小窗口沿用现有窄屏样式，必要时工具栏换行，避免按钮遮住标题或关闭按钮。

800px 是基于当前代码和截图提出的固定初值；实施时在实际 Obsidian 中确认缩放后的视觉效果，不能仅凭截图像素判断 CSS 宽度。

## 8. 验收标准

1. 旧的 RSS 60 分钟和公众号 60～90 分钟配置分别显示为 1 小时和 1～1.5 小时；保存再打开保持数值；非法范围有明确提示。
2. 普通 RSS 到期更新不启动公众号程序；计时器调整后不重复刷新，手动刷新与定时刷新共用去重。
3. 省电模式下，插件重开可直接显示上次公众号列表；完整缓存文章无需启动服务就能阅读和归档。
4. 公众号到期只拉起一个共享实例，等待任务完成和缓存写入后退出；保持侧栏打开并等待至少两分钟，不会被空闲轮询重新拉起。
5. 同步超过租约时长仍可完成；扫码中、图片补读中、其他库采集中不会被误关；客户端异常退出后能够最终回收。
6. 退出、睡眠后恢复以及过期调度快照均不会补跑大量历史周期；登录失效不会持续拉起服务。
7. 本机 RSS 的常驻模式可持续访问；最后一个常驻需求释放后，恢复安全空闲退出。
8. 单篇、订阅、分组和全局标记覆盖失败文章与分页隐藏条目，保留收藏及归档信息；撤销有效，保存失败会恢复。
9. 后台失败不自动已读；用户打开失败页会已读；快速切换、关闭和手动标未读不会被旧响应覆盖。
10. “已读”筛选准确；“全部文章”“已读”无数字；订阅源和未读计数即时更新，失败重试不会重置已读。
11. 深浅主题、长标题、长代码、图片、宽表格和窄窗口均可正常阅读；800px 外框、缩小后的边距、关闭按钮与导航没有遮挡。

实施时扩展现有 `feeds.test.ts`、`modal.test.ts`、`runtime.test.ts`、`runtime-integration.test.cjs`，针对调度、会话、快照和阅读状态补充行为测试；执行构建与相关测试。布局需在 Obsidian 中目视确认，完整安装包还需验证附属进程确实退出，不能只以释放租约代替验收。
